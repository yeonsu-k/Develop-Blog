> 이 글은 26년 6월 기준이다. 결과적으로 봇 제작에는 성공했지만, 모델을 무료로 가져다 쓰던 GitHub Models가 6월 중순에 신규 가입이 중단됐고 26년 7월 30일에는 완전히 종료되면서 이 글의 방식 그대로는 쓸 수 없게 됐다. 따라서 작업하실 분이 있다면 주의 바랍니다.

요즘 Claude, GPT가 앞다퉈 새 기능을 내놓는다. 스킬, 마켓플레이스, MCP까지...<br />
나는 개발자라 이런 기능들이 있다는 걸 알고 있고, 작업을 시작할 때 쓸 만한 스킬이나 플러그인이 있는지 확인하는 편이다.

어느 날 친구가 자소서를 쓰는데 GPT로 쓴다고 하길래, 혹시 플러그인 같은 것도 같이 쓰냐고 물어봤다.
"그게 뭔데?"라는 답이 돌아왔다. 나한텐 익숙한 것들이지만 관심 없는 사람한텐 낯설겠다는 걸 처음 체감했다.

## 일반 사용자가 MCP 세팅을 할 수 있을까

마침 그 무렵 회사에서 기획이나 회계 업무를 하는 동료들에게도 AI를 지원하자는 얘기가 나왔다. 이때 팀장님이 이분들이 직접 MCP 세팅하고 스킬 세팅해서 쓰는 게 힘들지 않을까? 하셨다.

사내에서 운영하는 만큼 회사 계정으로 운영할 수 있어야 하고, 스킬이나 MCP는 공용으로 세팅해 두되 사용자간 메시지 내용이 서로 공유되면 안 된다.
그래서 팀장님이 이미 쓰고 있는 메신저인 Teams에 봇을 만드는 게 가장 좋지 않을까 하셨다.

## 실패했다

그렇게 Teams에 봇을 만드는걸 한 번 시도해봤다가 실패했다. 단순히 Teams에 플러그인을 추가하는 걸로는 안 됐고, 그때는 Teams에 봇을 만들려면 Copilot Studio를 써야 했다.
테스트로 Copilot Studio에 한달 무료 평가판에 날씨 MCP 무료인 걸 세팅해봤다. 테스트 패널 챗으로 테스트해봤을 때 세팅을 잘 못한건지 새 세션에 첫 질문만 가능하고 대화를 이어나갈 수 없었다.

무료 평가판이라서 그런가 하고 알아봤을 땐 기존에 쓰던 GitHub Copilot과는 다른 제품이라 별도 비용이 정기적으로 꽤 필요했다. 결국은 봇 작업은 미루게 되었는데 마침 Copilot Dev Days라는 MS에서 운영하는 컨퍼런스를 가보게 되었다.<br />
(Copilot은 마이크로소프트(MS)가 개발한 서비스 제품이다.)

컨퍼런스 내용은 [Copilot Dev Days 후기](https://develop-blog-ten.vercel.app/blog/github-copilot-dev-days)에 적어뒀다. 강연이 끝나고 MS에서 근무하시는 발표자님을 따로 찾아가 Copilot Studio 없이도 봇을 만들 수 있는지 여쭤봤다.
굉장히 밝게 방법이 있다고 말씀해주셨다. 구체적으로 알려주시진 않았지만 찾아보면 있을 거라고 확신을 갖고 말씀해주셔서 다시 해볼 마음이 생겼다.

## Teams로 회사 봇 만들기

뼈대는 Microsoft 365 Agents Toolkit의 Teams AI 봇 템플릿으로 잡았다. 메시지를 받고 답하는 구조가 이미 들어 있어서, 내가 만질 건 AI가 뭘 하게 할지였다.
비용은 최대한 쓰지 않으려고 Azure App Service 무료 요금제(F1)로 배포했다.

친숙함을 위해 Teams 봇에 이름도 붙였다. 사내 봇 만드는 데 같이 고민했던 직장 동료께서 `조랭이`라는 이름을 추천해주셨다. 줄여서 `쪼`라고 해도 호출할 수 있도록 세팅했다.

### LLM은 GitHub Models로

LLM도 무료로 쓰고 싶었다. GitHub Models는 GitHub 토큰으로 호출할 수 있었고, 내 기억으로는 당시 무료로 쓸 수 있는 모델 중 가장 최신이 `gpt-4.1`이라 이걸 썼다.

### 사내 정보와 MCP 연결

대화만 되는 봇이면 ChatGPT와 다를 게 없어서 두 가지를 붙였다.

먼저 사내 정보들을 md 파일로 만들어뒀다. 간단한 프로젝트 설명, 복지, 휴가, 구성원, 소소하게는 점심은 주로 어디서 먹는지 까지 md 파일로 만들어 두고, 봇이 이 파일들을 읽어서 시스템 프롬프트에 넣는다.
앞으로도 정보를 추가할 때는 md 파일을 하나 만들고 index.md에 링크를 걸면 된다.

그다음 MCP 연결 테스트용으로 웹 검색(Tavily), 한국 법령 조회(Korean Law), 날씨(Weather) 세 개를 연결했다.
MCP 서버 목록은 설정 파일 하나에 모아뒀고, 추가할 때는 이 파일에 항목만 넣으면 된다.

```ts
export const MCP_SERVERS = [
  { name: 'Tavily', package: 'tavily-mcp', enabled: !!config.tavilyApiKey },
  { name: 'Korean Law', package: 'korean-law-mcp', enabled: !!config.lawOcKey },
  { name: 'Weather', package: '@dangahagan/weather-mcp', enabled: true },
  // 새 MCP는 여기에 추가
]
```

질문에 든 키워드를 보고 필요한 MCP만 불러오도록 했다. 법령 관련 키워드면 Korean Law, 날씨 관련 키워드면 Weather를 쓰고, Tavily는 항상 붙는다.

그런데 배포하고 나니 질문에 따라 속도 차이가 났다.
사내 정보는 서버 안의 md 파일에서 가져오니까 빠른 편이었고, MCP로 외부 API를 거쳐 와야 하는 것들(법제처 데이터)은 다소 느린 편이었다.

## 배포

봇을 Teams에서 쓰려면 Azure 리소스 만들기, 봇 등록, 앱 패키지(매니페스트) 만들기, 검증, 배포까지 거쳐야 한다. VS Code에서 Microsoft 365 Agents Toolkit으로 배포했다.

처음엔 사내 정보만 배포하고, MCP를 추가해서 Azure에 배포했는데 MCP가 업데이트가 안 된 것처럼 보였다.
알고 보니 세팅과 관련된 변경은 `provision`을 누른 뒤 `deploy`를 해야 하고, 내용만 바뀌었으면 `deploy`만 해도 충분했다.

Azure 포털에는 상태를 확인할 수 있는 버튼이 엄청 많았다. 용량, 최신 업데이트 날짜, 실제로 올라간 코드의 폴더 구조 같은 걸 찾는 것조차 익숙하지 않아서, 하나하나 AI의 도움으로 어디를 눌러야 하는지 알아냈다.
(아직도 헷갈린다...)

Teams 앱 업로드에는 권한이 없어서 팀장님의 승인이 필요했다.
기본적으로 세팅된 환경으로 올렸더니 Teams 앱 목록에는 `teams-ai-botdev`라는 이름으로 게시됐다.
첫 공개된 팀즈봇 이름에 dev가 붙게된거다.(ㅠㅠㅠ)

### F1 용량 문제

F1의 디스크 용량은 1GB까지다. MCP 3개를 연결해보고 잘되길래 신이 나서 파일 업로드되는 MCP를 하나 더 붙여보려다가 용량 제한에 걸렸다.
용량을 확인해보니 사내 정보 + MCP 3개가 960MB 정도됐던걸로 기억한다.(캡쳐를 안해둬서 기억에 의존)

MCP를 많이 연결해서 사업이나 회계 쪽에서 많이 쓰게 하고 싶었는데, MCP 하나만 더 연결해도 무료 요금제의 한계를 넘는 상황이었다.
F1 다음이 B1이였는데 Azure서버에 할당되어 있는동안 가격이 측정되어서 봇 특성상 서버를 끌수도 없는터라 비용부담이 클거같아 F1에서 이정도로 작업을 멈추게 되었다.

## 결과

마침 6월 마지막 주에 신입이 들어오기로 해서, 처음에는 사내 정보만이라도 잘 답해주는 걸 목표로 작업했다. 예상보다 일찍 테스트가 끝나서 MCP도 연결했다.

첫 버전의 봇은 사내 정보를 답하고, 검색과 법령 조회도 했다. 개발자가 아닌 사람도 MCP를 몰라도 Teams에서 말만 걸면 되는 구조가 됐다.

무료로 이 정도 결과물이면 만족스럽다. 다만 서버 비용을 늘려서 여러 가지 MCP를 연결할 수 있었다면 확장성은 훨씬 컸겠다는 생각이 들었다.
