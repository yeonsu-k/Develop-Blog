마이크로소프트 13층에서 열린 GitHub Copilot Dev Days에 낮 12시부터 저녁 6시까지하는 컨퍼런스를 다녀왔다.

회사에서 Copilot을 이미 Enterprise로 쓰고 있었고, Copilot을 활용해서 부서 상관없이 신입이나 비전공자도 쓸 수 있는 Teams용 사내 봇을 만들어보려 했는데, 잘 안 됐었다.
Copilot을 제대로 쓰고 있는 건지도 궁금했고, 그때 만들지 못한 봇도 방법이 있을지 궁금해서 참여하게 됐다.

시작하자마자 참석자들이 실제로 사용하는 AI 도구는 뭔지 설문을 했는데, 클로드가 60%에 가까웠고, 정작 이 행사의 주인공인 코파일럿은 20%, 커서가 10% 정도였다.
코파일럿 행사에 와서 코파일럿을 안 쓰는 사람이 더 많다는 게 신기했다.

## 비전공자도 코파일럿을 이렇게 쓴다

첫 세션은 비전공자가 GitHub Copilot을 실무에 어떻게 붙이는지에 대한 이야기였다.
SharePoint 공유폴더를 매개로 팀 전체가 Copilot을 함께 쓰는 구조를 소개했는데, 핵심은 크게 세 가지였다.

**copilot-instruction.md**라는 파일을 하나 만들어서 팀의 모든 컨텍스트를 한 파일에 몰아넣는다.
우리 팀이 누구인지, 무슨 일을 하는지, 어떤 용어를 쓰는지, AI가 답할 때 지켜야 할 톤과 거절해야 할 것까지 담는다.
발표자가 표현한 방식이 재밌었는데, 프로그래밍하듯 쓰는 게 아니라 새로 온 팀원에게 사무실을 안내하는 느낌으로, "이 자료는 어디 있고 이건 누구한테 물어보고" 하는 식으로 자연어 약 500줄을 채웠다고 한다.

`prompts/` 폴더는 한 번 만들어두면 `/명령어`로 바로 부를 수 있는 반복 작업 단축키다.
주간보고, 회의록 정리, 메일 초안처럼 매번 새로 쓰기 귀찮은 일들을 줄일 수 있다.
발표자 분께서는 `/grill-me`라는 이름으로 명령어를 만들어서 AI가 나한테 질릴 때까지 질문하게 해서 일을 시작하기 전에 빠진 게 없는지 스스로 점검했다고 한다.

`skills/` 는 필요할 때만 꺼내 쓰는 매뉴얼 겸 도구 모음이었다.
PPT 슬라이드 형태의 HTML을 만들어주는 frontend-design, 브라우저를 직접 조작하는 agent-browser 같은 것들을 예로 들었다.

Copilot의 모드도 여러가지가 있다. Ask/Plan 모드는 답변과 계획을 받는 용도고, Agent 모드는 파일 생성·수정이나 터미널 실행까지 맡기는 모드다.
Agent는 메일을 보내거나 공유 폴더에 파일을 올리는 것처럼 외부와 직접 소통하지 못한다. 이 부분은 Power Automate가 대신 처리하고, SharePoint를 거쳐 팀 미팅을 잡는 것도 채팅으로 해결한다고 했다.
AI가 못 하는 부분을 자동화 도구가 대신 처리하는 구조가 실용적으로 느껴졌다.

## Copilot CLI와 SDK

두 번째 세션은 CLI와 SDK를 홍보하는 자리에 가까웠다.

### Copilot CLI

다음은 Copilot CLI에서 사용할 수 있는 명령어들이다.

- `!`를 붙이면 그 자리에서 쉘 명령어를 칠 수 있다
- `/delegate`: 로컬이 아니라 클라우드에서 작업을 이어갈 수 있게 해준다
- `/fleet`: 세운 계획을 하위 에이전트들이 병렬로 실행한다
- `/review`: 명령어 뒤에 sonnet, opus를 붙이면 여러 모델에게 각각 리뷰를 맡길 수도 있다
- `copilot -p`: 헤드리스로 코파일럿을 부르는 명령어다. GitHub Actions에서 PR이 열릴 때마다 이걸 호출해 변경사항 분석이나 취약점 탐지를 시킬 수 있고, 자동 테스트 생성이나 빌드 실패 분석도 가능하다고 한다
- `/research`: 코파일럿 관련 GitHub 저장소와 웹을 뒤져서 정보를 모아주는 리서치 전용 에이전트
- `/yolo`: 자동 승인. 이름 그대로다
- `Shift+Tab`: Copilot 모드 변경

### Custom Agents

어떤 tool을 쓰고 어떤 MCP를 붙일지 정해서, 직원 한 명을 통째로 에이전트로 만드는 느낌이라고 표현했다.
[github/awesome-copilot](https://github.com/github/awesome-copilot/) 저장소에 프론트엔드 성능 최적화나 context7 활용처럼 참고할 만한 스킬·에이전트가 많다고 소개했다. 실제로 훑어보니 참고할 만했다.

### Copilot SDK

Copilot SDK, 즉 내 앱에 AI 기능을 직접 붙이는 방법을 다루기로 되어 있었다.
그런데 SDK는 진짜 개발자용이라 실습까지 보여주기엔 참석자 수준 차이가 컸고, 시간도 부족해서 발표자가 결국 CLI 활용법만 다시 설명하고 마무리했다.
살짝 아쉬웠지만, 한편으로는 SDK를 붙이는 난이도가 그만큼 높다는 뜻으로 이해했다.

## 다녀온 소감

행사 막바지에는 6월 20일에 "입코딩 대회"가 열린다는 공지를 들었다. 작년에도 재밌게 봤던 대회였는데 올해도 열린다니 어떤 사람이 어떤 결과를 보여줄지 기대된다.

설계는 Claude, 구현은 Codex, 리뷰는 Copilot이라는 조합을 발표자가 추천했다.
도구 하나로 다 해결하기보다 강점대로 나눠 쓸 수 있다는 게 코파일럿의 장점이라고 다시 한번 생각하게 됐다.

행사장을 나오면서 든 생각은, 결국 AI 도구 이름과 상관없이 방식은 비슷하다는 거였다.
md로 프로젝트 설명을 넣고, 반복 작업은 명령어로 줄이고, 필요할 때만 스킬을 꺼내 쓴다.
Claude Code를 쓰면서 이미 하고 있던 것들과 크게 다르지 않았다.
사내에서는 Copilot도 지원해주고 계셔서, 지금까지 업데이트 된걸 내가 잘 따라오고 있었구나 싶은 컨퍼런스였다.

컨퍼런스 듣기 전에 팀즈에 봇을 만들려면 Copilot Studio라는 도구를 결제해야만 했어서 결국 실패로 돌아갔었다.
컨퍼런스가 끝나고 MS에서 근무하시는 발표자님을 따로 찾아가 Copilot Studio 없이도 봇을 만들 수 있는지 여쭤봤는데, 방법이 있다고 하셨다.
구체적인 방법을 알려주신 건 아니지만, 찾아보면 방법이 있을 거라고 하셨다. 확신을 가지고 말씀해주셔서 다시 시도해볼 용기를 얻었다.
